# CFMMC 期货交易复盘系统

中国期货市场监控中心（CFMMC）投资者查询系统 —— 数据抓取、结算单解析、Web 交互式复盘分析。

## 功能特性

- **数据抓取**：自动登录监控中心，下载逐日盯市 / 逐笔对冲 XLS 结算单（支持验证码自动识别）
- **智能解析**：兼容两种报表格式（逐日盯市 / 逐笔对冲），正确处理期货与期权成交汇总
- **Web 复盘平台**：Flask 前后端分离架构，浏览器中直接查看分析结果
  - 总览卡片：总盈亏（期货+期权）、分项明细、净盈亏
  - 账户权益走势：客户权益 / 当日结存 / 保证金占用 / 可用资金，附区间权益变动与**最大回撤**
  - 品种盈亏纵览：按品种汇总手数/盈亏/手续费，支持排名
  - 每日累计趋势图
  - 品种详情弹窗（点击品种名）
  - TOP 盈亏成交排行
- **品种筛选（v3.1 新增）**：扫描全市场主力合约，找出「价格逼近长期高点/低点」的品种，
  并用均线、MACD、布林带、量能等技术指标打分排序，支持一键加入自选

## 快速开始

- Python **3.10+**（代码使用了 `str | None`、`list[str]` 等 3.10 才支持的语法）
- 依赖包：

```bash
pip install requests ddddocr xlrd pandas matplotlib openpyxl pillow beautifulsoup4 flask flask-cors chinesecalendar
```

1. **登录**：在 Web 页面输入期货账号和验证码登录监控中心
2. **选择日期范围**：支持"今日/本周/本月/上月/全部"快捷选择或自定义
3. **查询复盘**：点击"查询复盘"，系统会：

4. **查看详情**：点击品种名称弹出该品种的所有成交明细

## 品种筛选（v3.1 新增）

页面右上角切换到 **🔍 品种筛选**。

### 它解决什么问题

复盘是「回看已经做过的交易」，筛选是「找接下来该看的品种」。
核心条件：**当前价格距离长期高点 / 低点已在阈值（默认 5%）以内**，
即「即将突破」或「刚刚突破」，再用技术指标判断这个突破的质量。

### 数据来源与口径

| 项 | 取值 |
| --- | --- |
| 合约 | 各品种**主力连续合约**（新浪 `XX0`） |
| 日线 | 新浪财经公开接口，覆盖从上市至今的完整历史 |
| 实时价 | 新浪实时快照，盘中会覆盖/追加当日 K 线，因此盘中也能抓到「正在逼近」 |
| 品种池 | 75 个活跃品种，覆盖上期所/能源中心/大商所/郑商所/中金所/广期所 |
| 缓存 | 内存 + `cache/market/*.json`，默认 10 分钟 TTL，页面有「刷新行情」按钮强制更新 |

**关键点位口径（重要）**：长期高点/低点一律取**不含当日**的前 N 根 K 线，
`shift(1).rolling(N)` 语义。若把当日算进去，当日创新高时距离恒为 0，
就无法区分「正在逼近前高」和「刚刚突破」了。

**已知局限**：

1. 主力连续合约在**换月**时存在价格跳空（新旧合约价差），因此超长期高低点
   可能包含换月缺口造成的失真。本工具不做复权处理，界面上已标注数据口径。
   判断「长期高点」时建议结合近 1 年等较短窗口交叉验证。
2. 盘中最后一根 K 线是未收盘的实时快照，尾盘前指标会随价格抖动。
3. 免费公开接口，无 SLA；接口异常时自动退回本地缓存并标记为过期数据。

### 评分模型（满分 100）

> **权重经过回测校准（v2）**，完整依据见 [BACKTEST.md](BACKTEST.md)：
> 480 个交易日 × 3.4 万样本、换月复权数据。在「候选集内部取前 5 名」这个
> 真实用法下，评分的 20 日超额收益 **+0.81%、t = 5.34、胜率 62.5%**。

| 维度 | 权重 | 看什么 |
| --- | --- | --- |
| 关键点位临近度 | 28 | 距前高/前低还差百分之几。**越近分越高，已突破直接满分** |
| **20 日动量** | **30** | 过去 20 个交易日的涨跌幅，**按信号方向对齐**（靠近前高看涨、靠近前低看跌）。回测 IC +0.036（t=2.80） |
| 均线结构 | 14 | 收盘价与 MA5/10/20/60 是否顺着突破方向排列（趋势确认） |
| MACD | 10.5 | DIF/DEA 相对位置、是否在零轴上方、金叉/死叉、柱体扩张还是收敛 |
| 布林带 | 10.5 | 带宽是否处于低分位（**收口 = 变盘前夜**）、价格在中轨哪一侧、%B 位置 |
| 量能 | 7 | 量比（当日量 / 前 20 日均量） |

动量维度的加入方式：原有五维按 **0.7 等比缩放**，腾出 30 分给动量。
这样既保留原有组合的有效部分，又叠加了独立的动量信号——实测在候选集内
5 日超额 **+0.106%（t=2.34，显著）**、20 日 +0.197%（方向一致）。

方向判定：哪边更近就按哪边算——逼近前高记为**多头**，逼近前低记为**空头**。

信号标签：

- `逼近前高 / 逼近前低`：距离在阈值一半以内
- `接近前高 / 接近前低`：在阈值内但还不到一半
- `已突破前高 / 已突破前低`：当前价已越过关键点位

### 数据口径：换月复权

筛选器默认使用**换月复权**后的主力连续序列（`adjusted=1`，可传 `adjusted=0` 关闭）。

原因：新浪的 `CU0` 这类主力连续是拼接出来的，换月那天价格会从旧合约跳到新合约。
实测 15 个品种，**跳空平均是正常日波动的 2.06 倍**，玻璃（FG）达 **5.51 倍、单次 15.56%**。
不处理会直接污染：

- 「前高 / 前低」本身 —— 一条 15% 的假跳空足以凭空造出一个"前高"
- 所有动量类指标（假涨假跌）
- ATR / 均线 / 布林带

做法（`contracts.py`）：逐个拉取单个合约日线（含持仓量），每天取**持仓量最大**的
合约为当日主力，再按 `r = P_新 / P_旧` 做**比例后复权**。最新价保持真实，
所以实时快照可以直接叠加。首次构建会缓存到 `cache/`，之后加载 <1 秒。

## 盈亏计算说明

| 指标     | 说明                                                                                                                                    |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 期货盈亏 | 逐笔对冲报表中的平仓盈亏 / 逐日盯市报表中的当日盈亏                                                                                     |
| 期权盈亏 | **FIFO 开平仓匹配后的已实现盈亏**：同一合约内按先进先出配对，盈亏记在平仓那一笔上；`盈亏(元) = 权利金价差(点) × 手数 × 合约乘数(元/点)`。乘数优先由结算单反推（\|权利金总额\| ÷ 单价 × 手数），反推失败时查内置乘数表；配对基于**全部历史数据**，即使开仓日在查询窗口之前，跨窗口平仓也能算出正确盈亏 |
| 期权到期 | **虚值到期按 0 价格强制结算**：虚值到期不产生任何成交行，持仓只是从持仓汇总消失。系统按合约代码推算到期日（见下），把到期后仍未平仓的头寸平掉 —— 买方记为权利金全额亏损，卖方记为权利金全额收入，明细里以 `到期作废` 行展示 |
| 期权行权 | **实值到期按内在价值结算**：实值期权会被行权，这一笔记在结算单的「期权行权明细」区块，**不在「期权成交汇总」里**。系统把它翻译成一笔等效平仓成交（价格 = 行权盈亏 ÷ (手数 × 乘数)），走同一条 FIFO 路径，明细里以 `行权` 行展示，手续费也一并计入 |
| 期权权利金收支 | 现金流口径（买方支出为负、卖方收入为总览参考项），与已实现盈亏分列展示                                                              |
| 总盈亏   | 期货平仓盈亏 + 期权已实现盈亏                                                                                                           |
| 净盈亏   | 总盈亏 - 全部手续费（期货+期权）                                                                                                        |

> 注意：已实现盈亏不含期末未平仓头寸的浮动盈亏；期权明细表中 `open_volume/close_volume`
> 列标出每笔成交的开仓/平仓拆分，期末未平仓手数见查询结果 `opt_open_positions`，
> 页面顶部会汇总提示。
>
> **胜率 / 盈亏比**按「期货 + 期权的已实现盈亏」合并统计，品种汇总页与品种详情页
> 使用同一套口径（`review.compute_pnl_stats`）。全部亏损时盈亏比为 `0.00`，
> 只在「有盈利且无亏损」时才显示 `∞`。

### 期权合约乘数（关键，容易算错）

期权权利金按「点」报价，换算成人民币必须乘以合约乘数。口径很统一：

> **1 点 = 标的期货的「交易单位」**

所以 `合约乘数(元/点) ≡ 标的期货交易单位`。几个容易踩坑的：

| 品种 | 交易单位 | 乘数 | 说明 |
| --- | --- | --- | --- |
| 沪铜 CU | 5 吨/手 | **5** | |
| 沪金 AU | 1000 克/手 | **1000** | |
| 原油 SC | 1000 桶/手 | **1000** | 上期能源，曾被整组遗漏 |
| 多晶硅 PS | 3 吨/手 | **3** | 广期所，曾被整组遗漏 |
| 工业硅 SI | 5 吨/手 | **5** | 广期所 |
| 碳酸锂 LC | 1 吨/手 | **1** | 广期所 |
| 集运欧线 EC | — | **50** | 合约乘数直接规定为 50 元/点 |
| 鸡蛋 JD | 5 吨/手，报价 元/500千克 | **10** | 报价单位不是元/吨，不能直接用 5 |
| 原木 LG | 90 立方米/手 | **90** | |
| 2 年期国债 TS | 面值 200 万 | **20000** | 其余国债（T/TF/TL）面值 100 万 → 10000 |

**取值优先级**（`review.resolve_multiplier`）：

1. 结算单反推：`|权利金总额| ÷ (单价 × 手数)`，最准确、自动适配任意新品种
2. 反推失败（权利金列为空/为 0）→ 查内置乘数表
3. 两者都没有 → 按 1.0 计算，**同时产生告警**，页面顶部横幅会显示
   「品种 X 的期权合约乘数未知，盈亏可能严重失真」

第 3 种情况必须让用户看见：原油这类品种若按 1.0 计算，盈亏会被缩小 1000 倍，
而且从结果上完全看不出来。反推值与内置表相差超过 2% 时也会告警提示核对。

> 新增期权品种时请同步 `review.OPTION_MULTIPLIER`；
> `tests/test_option_multiplier.py` 会检查常见期权品种是否都有乘数。

### 期权到期日（到期作废怎么结算）

虚值到期作废时，结算单里**没有平仓成交行**，持仓直接从持仓汇总里消失。
如果只按成交行做 FIFO，这笔仓位会永远停在"未平仓"，买方付出的权利金
（全额亏损）在复盘里就消失了。所以系统按合约代码推算到期日，把到期后
仍未平仓的头寸按 0 价格强制结算：

| 品种类型 | 到期日规则 |
| --- | --- |
| 中金所股指期权 IO / MO / HO | 合约月份**第三个星期五**（遇节假日顺延） |
| 中金所国债期权 T / TF / TS / TL | 合约月份**第二个星期五**（遇节假日顺延） |
| 上期所 SHFE（铜/铝/锌/黄金/白银/螺纹…） | 标的期货交割月前一月的**倒数第 5 个交易日** |
| 上期能源 INE（原油/低硫燃料油/20号胶/国际铜） | 前一月的**倒数第 13 个交易日** |
| 大商所 DCE（豆粕/玉米/铁矿石/生猪…） | 前一月的**第 12 个交易日**（2501 合约起由「第 5 个」延后） |
| 郑商所 CZCE（白糖/棉花/PTA/甲醇…） | 前一月**第 15 个日历日（含）之前的倒数第 3 个交易日** |
| 广期所 GFEX（工业硅/碳酸锂/多晶硅/铂/钯） | 前一月的**第 5 个交易日** |

> 各交易所规则**并不统一**，不能一刀切。早期版本对所有商品都用「前一月第 5 个
> 交易日」，会让上期所/上期能源/大商所的合约提前 1~2 周被判定为到期 ——
> 这比不结算更危险：提前按 0 平仓后，真实平仓又会开出一笔反向仓，造成重复计账。
> 现在按交易所分别处理，并且**对未收录的品种一律不结算**（只提示人工核对），
> 绝不用猜的规则。

作废盈亏（权利金全额）：

- 买方（付出权利金）→ `-(开仓价 × 手数 × 乘数)`，即全额亏损
- 卖方（收取权利金）→ `+(开仓价 × 手数 × 乘数)`，即全额收入

**安全网**：如果某合约在推算出的到期日**之后仍有成交**，说明到期日推算有误，
系统会跳过结算、不会把仍在交易的合约强行平仓。数据若还没覆盖到到期日，也不会结算。

**区分作废与行权**：结算单里「期权行权明细」区块存在且有该合约，就按**行权**处理；
没有则按**作废**处理。所有处理过的合约都会在页面顶部横幅列出（含合约、方向、手数、
金额），便于核对。

> 未安装 `chinesecalendar` 时，商品期权的到期日只能按"排除周末"推算，
> 可能比真实到期日早几天（**盈亏金额不受影响，只是记账日期可能偏早**），
> 横幅里会标注"日期近似"。装上之后该标注会自动消失。

## 鲁棒性说明

- **无成交日**：结算单可以只有资金状况、没有任何成交行，解析不会报错
- **无效结算单文件**（登录过期时监控中心返回 HTML 却存成了 .xls）：自动识别魔数并跳过。
  数量少（≤20）时自愈改名为 `.bad` 以便重新下载；数量多时**不会**批量改名（避免在用户
  磁盘上产生几百次重命名），只提示用 `python review.py --clean-bad` 统一清理
- **月报不会被误当日报**：只扫描 `日报/逐笔`，`月报/逐笔` 会被跳过并在日志中说明
  （月报是月度汇总单据，若被当成某一天的逐笔数据会覆盖同日的日报）
- **多账户同一天**：目前缓存以日期为键，只保留最后一个账户的数据。检测到这种
  情况时会在日志里明确告警（列出哪天的哪个账户被覆盖），不会静默丢数据。
  需要统计多账户合计时，请为每个账户使用独立的 `output_dir`
- **期权乘数未知**：不会静默按 1.0 计算，而是产生告警并在页面顶部横幅展示
- **期权到期作废**：按到期日强制结算（详见上文），不会因为"没有平仓成交行"而丢失亏损
- **空窗口不串数据**：查询与本地数据完全不相交的时间段时，各项盈亏均为 0
  （此前会把全历史的期权盈亏错误地显示出来）
- **并发安全**：每个请求使用独立的分析引擎（只共享只读的结算单缓存），
  数据缓存的重新加载是「整体替换」而非原地插入，避免并发请求互相污染或
  触发 `dictionary changed size during iteration`
- **长时间区间**：每日趋势返回完整日期（YYYY-MM-DD，跨年不重复），前端图表默认聚焦
  最近 60 个交易日并提供底部滑块，可完整缩放浏览全部区间
- **两种结算单都支持**：监控中心提供「逐笔对冲」和「逐日盯市」两种日报，系统
  **两者都读**（同一交易日都有时优先逐笔）。只下载了其中一种时不会出现"大量数据缺失"。
  两种报表的成交汇总都带「平仓盈亏」列，口径一致
- **数据目录自动纠正**：配置里写 `./output` 但实际数据在上一级目录时，会自动向上
  找同名目录并提示，避免"界面上什么都没有"的误判
- **列顺序不写死**：成交汇总的列位置各家券商/各版本并不一致（实测表头写的是
  **`买/卖`**、**`开/平`**，带斜杠）。解析改为**按表头关键字定位列**（匹配前先去掉
  `/`、`、`、空格），识别不出才回退旧版固定列；万一方向列仍取不到，再按单元格
  **内容**兜底识别。数值同时兼容千分位（`3,900.00`）、正号（`+0.00`）、括号负数、全角字符
- **缺失数据自动补下载**的日期范围不会超出今天；未来日期不会被误判为缺失
- **数据缺口分三类**（不再只报一个数字）：页面上的「数据缺口诊断」面板会分别列出
  - **真实缺口**：夹在已有数据之间的交易日 —— 真正需要补的
  - **早于已有数据**：本地最早日期之前的交易日，多为账户开立前，**不参与补下载**
  - **晚于已有数据**：本地最新日期之后的新交易日，可补
  - 另外单独列出**区间内休市**（元旦/春节/…）的天数，用来证明节假日确实被正确排除；
    「调休上班的周末」也会被正确判为非交易日（期货不交易）

  命令行模式下同样会打印这三类的明细。对应的 REST 接口是
  `GET /api/missing-dates?start=&end=`。
